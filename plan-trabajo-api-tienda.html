Plan de Trabajo — API Flujo Tienda

Fabricas de Credito QUAC — Construccion de APIs REST para el Flujo de Tienda (4 Bloques)

Version: 1.0
Fecha: 2026-04-27
Proyecto: Fabricas de Credito QUAC
Estado: Plan propuesto

Resumen Ejecutivo

Este plan de trabajo establece la hoja de ruta para construir las APIs REST que permiten ejecutar el Flujo de Tienda completo, desde el ingreso del cliente hasta la activacion del cupo. El flujo se divide en 4 bloques funcionales que agrupan 13 pasos y 18 servicios externos.

Resultado buscado: API completamente funcionales que permitan ejecutar el flujo de tienda desde la interfaz de la tienda fisica, incluyendo validaciones deidentity, calculo de cuotas, verificacion biometrica y activacion del credito.

Objetivo

Construir un conjunto de APIs REST que permiten ejecutar el flujo completo de solicitud de credito en una tienda fisica (Tienda QUAC), desde la captura del documento hasta la activacion del cupo preaprobado, siguiendo los diagramas Mermaid documentados en flujos/index.html.

Objetivos especificos

  • Bloque 1 (Ingreso): Validar documento, verificar existencia en ERP, consultar estado de cupo activo/bloqueado
  • Bloque 2 (Captura): Capturar datos del cliente, telefono, email, direccion, tokenizar consentimientos
  • Bloque 3 (Validaciones): Consultar listas restrictivas, buró de credito, evaluacion Preselecta, validacion FOSYGA, calculo de cupo
  • Bloque 4 (Resultado): Verificacion biometrica, activacion en UBICA, activacion del cupo

Alcance

Incluido:

  • Diseno de contratos de API (OpenAPI/Swagger)
  • Implementacion de endpoints REST
  • Integracion con servicios externos (ERP, Core Credito, Preselecta, FOSYGA, UBICA, Biometria)
  • Maquina de estados para control de flujo
  • Registro de invocaciones (logging)
  • Manejo de errores y reintentos

Excluido (fuera del alcance de esta fase):

  • Interfaz de usuario de la tienda (frontend)
  • Integracion con sistema de inventario/tienda (POS)
  • Flujo Web (autoservicio) - se documenta pero no se implementa
  • Flujo Externo (asesor de campo) - se documenta pero no se implementa

Fase 1: Ingreso del Cliente

El Bloque 1 maneja el ingreso inicial del cliente a la tienda: validacion de documento, consulta de existencia en ERP, y verificacion del estado de cupo (activo, bloqueado, cancelado).

Fase 2: Captura de Datos

Fase 3: Validaciones

El Bloque 3 ejecuta las validaciones de riesgo: listas restrictivas, bure de credito, evaluacion Preselecta, validacion FOSYGA/ADRES, y calculo del cupo. Este es el bloque con mas servicios externos.

6
POST /api/estudio/{id}/validar-listas

Consultar listas restrictivas. Retorna si el cliente esta en alguna lista negra.

7
POST /api/estudio/{id}/consultar-buro

Consultar bure de credito. Retorna score y historial crediticio.

8
POST /api/estudio/{id}/evaluar-preselecta

Ejecutar evaluacion de Preselecta. Retorna viabilidad y oferta preaprobada.

9
POST /api/estudio/{id}/validar-fosyga

Validar cotizacion en FOSYGA/ADRES. Retorna si esta activo y si cotiza en los ultimos meses.

10
POST /api/estudio/{id}/calcular-cupo

Calcular el cupo preaprobado basado en las validaciones anteriores.

Fase 4: Resultado y Activacion

El Bloque 4 muestra el resultado al cliente, ejecuta la verificacion biometrica, y si todo es correcto, activa el cupo en UBICA y genera la tarjeta virtual.

11
GET /api/estudio/{id}/resultado

Consultar el resultado del estudio. Retorna aprobado/rechazado con detalle.

Detalle de Tareas

Fase 1: Infraestructura Core (Dias 1-15)

  • T-001: Disenar esquema de base de datos
    Crear/verificar tablas: EstudiosCredito, PasosEstudio, HistorialEstados, RegistroServiciosExternos, EvaluacionesRiesgo
  • T-002: Implementar maquina de estados
    Crear stored procedure para transiciones de estado con validacion
  • T-003: Crear proyecto API base
    Configurar .NET Core / Node.js, estructura de carpetas, Middleware de logging
  • T-004: Implementar cliente HTTP para servicios externos
    Crear wrapper con reintentos, timeouts, circuit breaker

Fase 2: APIs del Bloque 1 (Dias 16-25)

  • T-005: POST /api/estudio/iniciar
    Endpoint para iniciar estudio. Valida documento contra ERP y CORE
  • T-006: GET /api/estudio/{id}
    Consultar estado de un estudio
  • T-007: Integracion ERP_QUAC
    Consumo de servicio de existencia de terceros
  • T-008: Integracion CORE_CREDITO
    Consumo de servicio de consulta de cupo/bloqueos

Fase 3: APIs del Bloque 2 (Dias 26-32)

  • T-009: POST /api/estudio/{id}/capturar-datos
    Capturar datos del cliente con validaciones
  • T-010: POST /api/estudio/{id}/capturar-direccion
    Capturar direccion de residencia
  • T-011: POST /api/estudio/{id}/consentimiento
    Tokenizar consentimientos con OTP
  • T-012: Integracion OTP_PROVIDER
    Consumo de servicio de envio de OTP (Infobip)

Fase 4: APIs del Bloque 3 (Dias 33-40)

  • T-013: POST /api/estudio/{id}/validar-listas
    Consultar listas restrictivas
  • T-014: POST /api/estudio/{id}/consultar-buro
    Consultar bure de credito
  • T-015: POST /api/estudio/{id}/evaluar-preselecta
    Ejecutar evaluacion Preselecta
  • T-016: POST /api/estudio/{id}/validar-fosyga
    Validar cotizacion FOSYGA/ADRES
  • T-017: POST /api/estudio/{id}/calcular-cupo
    Calcular cupo preaprobado

Fase 5: APIs del Bloque 4 (Dias 41-45)

  • T-018: GET /api/estudio/{id}/resultado
    Consultar resultado del estudio
  • T-019: POST /api/estudio/{id}/verificar-biometria
    Verificacion biometrica con AWS Rekognition
  • T-020: POST /api/estudio/{id}/activar-cupo
    Activar cupo en UBICA
