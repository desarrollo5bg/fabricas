Vista General

¿De que se trata esto?

Cuando un cliente quiere usar su credito QUAC por primera vez (o necesita reactivarlo), debe verificar su identidad tomandose 3 fotos desde su celular. Este proceso automatizado analiza las fotos en tiempo real para confirmar que la persona es quien dice ser.

📷

1. Selfie

El cliente se toma una foto del rostro mirando a la camara frontal del celular.

💳

2. Documento (frente)

Toma una foto de la parte frontal de su cedula de ciudadania, donde aparece la foto.

📄

3. Documento (reverso)

Toma una foto de la parte trasera de la cedula, donde estan la huella y los datos adicionales.

📱

Solo funciona en celulares. El proceso requiere acceso a la camara del dispositivo, por eso solo se puede hacer desde un celular. Si se intenta abrir desde un computador, se muestra un mensaje de error.

El proceso

¿Como llega el cliente aqui?

1

El cliente solicita credito QUAC en una tienda

Un asesor en la tienda inicia el proceso de activacion del credito desde el sistema interno.

2

Recibe un link por WhatsApp

El sistema genera un enlace unico de activacion y se lo envia al cliente por WhatsApp. Ese enlace contiene un codigo de referencia que identifica su sesion.

3

Abre el link en su celular

Al abrir el enlace, se carga la aplicacion de activacion. El sistema verifica que sea un celular y que el enlace sea valido.

4

Ve la pantalla de bienvenida

"¡Estas a solo un paso de activar tu credito QUAC!" — se muestra un checklist con las 3 fotos que debe tomar.

5

Toma las 3 fotos, una por una

Para cada foto, el sistema: muestra recomendaciones, abre la camara con una guia visual, deja confirmar la foto, la envia a validar, y muestra el resultado.

6

El sistema valida cada foto en tiempo real

Cada foto se analiza automaticamente usando inteligencia artificial (AWS Rekognition) para verificar calidad, identidad, y detectar fraudes.

7

Si todo esta bien, se activa el credito

Cuando las 3 fotos pasan la validacion, el credito se activa automaticamente (o se envia a revision manual si algo no coincide exactamente).

Checklist de la Selfie

Que verifica el sistema automaticamente cuando el cliente toma su foto de rostro.

📷

Selfie — Foto del rostro

Camara frontal del celular · Guia ovalada en pantalla

El sistema de inteligencia artificial analiza la selfie y verifica estos 7 puntos. Si alguno falla, se le pide al cliente que tome la foto de nuevo con instrucciones especificas de que corregir.

1
¿Se detecta un rostro humano?

El sistema necesita poder identificar una cara en la imagen. Si la foto esta muy oscura, demasiado lejos, o apuntando hacia otro lado, no va a detectar nada y pedira reintentar.

Umbral configurable: PERC_MIN_FACE (tipicamente 70-80%)
2
¿La foto es nitida y clara?

No puede estar borrosa, movida ni desenfocada. Una foto con mala calidad impide que el sistema pueda hacer comparaciones confiables contra el documento de identidad.

Umbral configurable: PERC_MIN_SHARPNESS
3
¿La cara se ve completa, sin nada que la tape?

La cara no puede estar parcialmente cubierta por una mano, un tapabocas, un gorro sobre la frente o cualquier objeto. El sistema necesita ver toda la cara: frente, ojos, nariz y boca.

4
¿La persona tiene lentes puestos?

No se permiten gafas de ningún tipo: ni lentes de sol ni lentes formulados (de formula). Los lentes generan reflejos y distorsiones que afectan la comparacion facial. Si el sistema detecta gafas, pide que se las retire.

5
¿La cara esta bien centrada en la foto?

El rostro debe estar dentro de la guia ovalada que aparece en pantalla. Si la cara queda muy a un lado, muy arriba, muy abajo, demasiado lejos o demasiado cerca, el sistema la rechaza. La app muestra un ovalo en la pantalla para ayudar al cliente a centrarse.

Limites configurables: CONF_BOUNDINGBOX (posicion, tamaño min/max)
6
¿Es una persona real frente a la camara?

Si esta funcion esta activada, el sistema verifica que hay una persona viva delante de la camara y no una foto impresa, la pantalla de otro celular, o una mascara. Esto se conoce como "prueba de vida" y es una de las defensas contra suplantacion de identidad.

Se activa/desactiva con: ENV_FACELIVENESS (1 = activo)
7
¿Esta persona es un suplantador conocido?

El rostro se compara contra una base de datos de personas que previamente han intentado suplantar la identidad de otros. Si el sistema encuentra una coincidencia (por encima del 90% de similitud), rechaza la foto inmediatamente y registra el intento como posible fraude. Esto protege contra personas reincidentes.

Umbral de fraude: FRAUD_IDENTITY_UMBRAL (tipicamente 90%)

Checklist del Documento (Frente)

Que verifica el sistema cuando el cliente toma la foto de la parte frontal de su cedula.

💳

Documento Frente — Cara con foto

Camara trasera del celular · Guia rectangular en pantalla

La foto frontal del documento se analiza de multiples formas: se verifica que sea un documento real, que la persona de la foto coincida con la selfie, y que el texto sea legible.

1
Requisito previo: la selfie ya debe estar aprobada

No se puede validar el documento sin tener primero una selfie aprobada. El sistema necesita la selfie para poder comparar la cara del documento contra la cara real del cliente. Si no hay selfie, se muestra un error pidiendo completar ese paso primero.

2
¿Es un documento fisico real? (no una fotocopia o captura de pantalla)

El sistema analiza visualmente la imagen buscando caracteristicas que identifican un documento real vs. una copia. Busca que aparezcan elementos tipicos de un documento de identidad (como hologramas, textura del material) y al mismo tiempo verifica que NO aparezcan elementos de fotocopia como bordes de pantalla, pixeles de monitor o marcas de impresora.

Configuracion de etiquetas: CONF_GEN_LABELS_FRONT
3
¿La foto del documento es nitida?

Similar a la selfie: la imagen debe ser clara y enfocada. Una foto borrosa del documento impide leer los datos y comparar la cara. Se necesita buena iluminacion, sin reflejos ni brillos sobre el documento.

Umbral configurable: PERC_MIN_SHARPNESS_FRONT
4
¿La persona del documento es la misma que tomo la selfie?

Esta es la verificacion principal de identidad. El sistema toma la foto que aparece en la cedula y la compara punto por punto contra la selfie que el cliente ya se tomo. Si la similitud entre ambas caras es menor al umbral configurado (tipicamente 80-90%), se rechaza indicando que no coinciden.

Umbral configurable: PERC_MIN_SIMILARITY (tipicamente 80-90%)
5
¿Se pueden leer los datos impresos en el documento?

El sistema extrae el texto del documento usando reconocimiento optico de caracteres (OCR) y busca palabras clave que deben aparecer en un documento colombiano valido (como "REPUBLICA DE COLOMBIA", "CEDULA", etc.). Si no encuentra un porcentaje suficiente de estas palabras, rechaza la foto por ser ilegible.

Umbral de texto legible: PERC_MIN_MATCH_FRONT_DOC

Checklist del Documento (Reverso)

Que verifica el sistema cuando el cliente toma la foto de la parte trasera de su cedula.

📄

Documento Reverso — Parte trasera

Camara trasera del celular · Guia rectangular en pantalla

El reverso del documento es el paso final de la validacion fotografica. Ademas de verificar que el documento es real, aqui se hace la validacion cruzada mas importante: comparar los datos del documento contra los datos registrados en el sistema.

1
Requisito previo: la selfie Y el frente deben estar aprobados

Las tres fotos se validan en orden estricto. No se puede tomar el reverso sin haber pasado primero la selfie y el frente del documento.

2
¿Es un documento fisico real?

Al igual que con el frente, se analizan las caracteristicas visuales para confirmar que es un documento original y no una fotocopia, captura de pantalla o replica.

Configuracion de etiquetas: CONF_GEN_LABELS_BACK
3
¿Se pueden leer los datos del reverso?

Se extrae el texto impreso en la parte trasera usando OCR. El sistema es inteligente y adapta lo que busca segun el tipo de documento que detecta:

  • Cedula colombiana estandar: busca textos como "REGISTRADURIA", datos del portador, etc.
  • Cedula de extranjeria: busca textos propios de la tarjeta de residencia.
  • Pasaporte: busca textos del formato de pasaporte.

Ademas, detecta textos que NO deberian estar ahi (como textos de un documento diferente al presentado).

Configuracion por tipo: CONF_GEN_TEXT_BACK (TR, DIG, PPT)
4
¿Los datos del documento coinciden con los datos registrados del cliente?

Esta es la validacion final y mas importante. El sistema toma todo el texto extraido de AMBOS lados del documento (frente y reverso) y lo compara contra los datos que tiene guardados en el sistema de credito QUAC. Especificamente verifica:

  • Nombre — que el nombre del documento coincida con el registrado
  • Apellido — que el apellido coincida
  • Numero de cedula — que el numero del documento sea el correcto (se prueban variantes con y sin puntos)
  • Fecha de expedicion — que la fecha de expedicion coincida (se prueban 3 formatos de fecha diferentes: DD-MM-AAAA, DD.MM.AAAA, etc.)

Si el porcentaje de coincidencia no es suficiente, el caso no se rechaza completamente sino que pasa a revision manual por un operador humano.

Umbral de coincidencia: PERC_MIN_MATCH_INFORMATION
Resultado

¿Que pasa cuando se completan las 3 fotos?

Cuando el cliente termina de tomar las 3 fotos, el sistema toma una decision automatica basandose en los resultados de todas las validaciones.

⚖ Arbol de decision

✅
Credito Activado

Las 3 fotos aprobadas Y los datos del documento coinciden con el sistema. El credito se activa automaticamente sin intervencion humana.

🔍
Revision Manual

Las fotos pasaron pero los datos no coinciden exactamente (ej: nombre con tilde vs sin tilde). Un operador revisa el caso.

📝
Enviado a Fabrica

Alguna foto fue rechazada o quedo en estado intermedio. El caso se envia al equipo de revision con los detalles del rechazo.

⚠

La activacion automatica se puede desactivar. Existe una configuracion (AUTOMATIC_ACTIVATION) que controla si el credito se activa solo o si siempre pasa por revision manual aunque todo este bien. Esto permite al equipo de riesgo tener control adicional cuando lo necesiten.

Como funciona por dentro

Arquitectura del sistema

El proceso involucra 2 sistemas propios y 3 servicios externos. Aqui se muestra como se comunican entre si.

CELULAR DEL CLIENTE │ │ El cliente abre el link de WhatsApp │ Se carga la app en el navegador del celular │ ▼ activacion-quac-client (App web en Vue 3) │ │ Envia las fotos como texto codificado (base64) │ Autenticacion con token de sesion │ ▼ api-activacion-v2 (Servidor Laravel — apirekognition.quac.co) │ ├──▶ AWS Rekognition (Inteligencia artificial de Amazon) │ ├─ Analisis facial (¿hay cara? ¿calidad? ¿lentes?) │ ├─ Comparacion de caras (selfie vs documento) │ ├─ Lectura de texto (OCR — extrae datos del documento) │ ├─ Deteccion de etiquetas (¿documento real o copia?) │ ├─ Prueba de vida (¿persona real o foto de foto?) │ └─ Busqueda de fraude (base de datos de suplantadores) │ ├──▶ AWS S3 (Almacenamiento en la nube) │ └─ Guarda todas las fotos con marca de agua │ └──▶ API QUAC (CRM) (Sistema de credito interno) ├─ Consulta datos del cliente ├─ Verifica estado de la cartera ├─ Compara datos del documento vs registrados └─ Activa el credito si todo esta bien
🔒

Seguridad: Todas las comunicaciones van cifradas (HTTPS). Las fotos se guardan con marca de agua que incluye fecha, hora e ID de la sesion. Ademas, toda solicitud queda registrada en un log para auditoria.
