RetosSeguridad (OTP)

Gestiona el ciclo de vida de los códigos OTP enviados al cliente para verificar su identidad durante el consentimiento. Soporta reenvíos y múltiples canales.

DDL de la tabla

CREATE TABLE RetosSeguridad (
    IdReto              INT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    TipoReto            VARCHAR(20)   NOT NULL
        CHECK (TipoReto IN ('OTP','PREGUNTA_SECRETA','VALIDACION_MANUAL')),
    Canal               VARCHAR(20)   NOT NULL
        CHECK (Canal IN ('WHATSAPP','EMAIL','SMS')),
    DireccionEnvio      VARCHAR(200)  NOT NULL,   -- teléfono o email destino
    CodigoHash          VARCHAR(255)  NOT NULL,   -- hash del OTP (nunca plano)
    FechaExpiracion     DATETIME2     NOT NULL,
    Intentos            INT           NOT NULL DEFAULT 0,
    Verificado          BIT           NOT NULL DEFAULT 0,
    FechaVerificacion   DATETIME2     NULL,
    NumeroReenvios      INT           NOT NULL DEFAULT 0,
    UltimoReenvio       DATETIME2     NULL,

    CONSTRAINT FK_Reto_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio)
);

Seguridad OTP. El campo CodigoHash almacena únicamente el hash del código (bcrypt o SHA-256 con salt). El código en plano nunca se persiste. Al validar, se compara el hash del código ingresado contra este campo.

ConsentimientosLegales

Registra la firma legal del cliente para el tratamiento de datos personales y las condiciones del crédito. Cada tipo de consentimiento tiene su propio mecanismo de firma (TipoFirma).

DDL de la tabla

CREATE TABLE ConsentimientosLegales (
    IdConsentimiento    INT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    TipoConsentimiento  VARCHAR(50)   NOT NULL,
    TipoFirma           VARCHAR(30)   NOT NULL
        CHECK (TipoFirma IN (
            'OTP_SMS','OTP_EMAIL','OTP_WHATSAPP',
            'CHECKBOX','FIRMA_DIGITAL')),
    TextoConsentimiento NVARCHAR(MAX) NOT NULL,   -- versión exacta del texto
    Firmado             BIT           NOT NULL DEFAULT 0,
    FechaFirma          DATETIME2     NULL,
    IdOperador          INT           NULL,
    HashDocumento       VARCHAR(255)  NULL,       -- hash del PDF generado

    CONSTRAINT FK_Consent_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio)
);

ValidacionesContactabilidad

Registra la validación de datos de contacto del cliente a través del servicio UBICA. Puede disparar una alerta de fraude si los datos no coinciden con registros conocidos.

DDL de la tabla

CREATE TABLE ValidacionesContactabilidad (
    IdValidacion        INT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    TipoContacto        VARCHAR(30)   NOT NULL
        CHECK (TipoContacto IN ('TELEFONO','EMAIL','DIRECCION','CELULAR')),
    DatoContacto        VARCHAR(200)  NOT NULL,
    EstadoUbica         VARCHAR(50)   NULL,       -- resultado libre del servicio UBICA
    Validado            BIT           NOT NULL DEFAULT 0,
    FechaValidacion     DATETIME2     NULL,
    IdAlertaFraude      INT           NULL,       -- FK a AlertasFraude si hay anomalía

    CONSTRAINT FK_ValidContact_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio),
    CONSTRAINT FK_ValidContact_Alerta FOREIGN KEY (IdAlertaFraude)
        REFERENCES AlertasFraude(IdAlerta)
);

Diccionario de columnas

ColumnaTipoNULLDescripción
IdValidacionINT IDENTITYNOPK autoincremental
IdEstudioINT FKNOEstudio validado
TipoContactoVARCHAR(30) CHECKNOTELEFONO | EMAIL | DIRECCION | CELULAR
DatoContactoVARCHAR(200)NOValor del dato de contacto a validar
EstadoUbicaVARCHAR(50)SÍResultado textual del servicio UBICA — sin CHECK fijo (campo libre)

EstadoUbica es campo libre. A diferencia de otros campos con CHECK, EstadoUbica es VARCHAR(50) NULL sin restricción de valores. El servicio UBICA puede evolucionar sus estados sin requerir un cambio de DDL.

EvidenciasFabrica

Almacena documentos, notas y comprobantes generados durante el proceso de crédito. No almacena fotografías ni datos biométricos — esos tienen su propia tabla (FotografiasEstudio).

Tipos fotográficos excluidos. El CHECK de TipoEvidencia no incluye SELFIE, DOCUMENTO_FRONTAL ni DOCUMENTO_TRASERO. Las fotografías se gestionan exclusivamente en FotografiasEstudio — decisión del PO documentada en GAP-07.

DDL de la tabla

CREATE TABLE EvidenciasFabrica (
    IdEvidencia         INT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    TipoEvidencia       VARCHAR(30)   NOT NULL
        CHECK (TipoEvidencia IN (
            'COMPROBANTE','NOTA_ASESOR',
            'DOCUMENTO_SOPORTE','OTRO')),
    NombreArchivo       VARCHAR(255)  NULL,
    RutaAlmacenamiento  VARCHAR(500)  NULL,    -- path o URL al blob storage
    MimeType            VARCHAR(100)  NULL,
    TamanoBytes         BIGINT        NULL,
    Descripcion         NVARCHAR(500) NULL,
    IdOperador          INT           NULL,
    FechaCreacion       DATETIME2     NOT NULL DEFAULT GETUTCDATE(),

    CONSTRAINT FK_Evidencia_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio)
);
