Información general del entorno

El entorno de pruebas de la API QUAC corre sobre un servidor Linux interno con exposición pública vía dominio corporativo. Todos los cambios de código se despliegan mediante FTP y se activan reiniciando el servicio apiquac-dev.service.

Ubicación de archivos y permisos

Los archivos compilados (resultado de dotnet publish) se alojan en la siguiente ruta dentro del servidor:

/home/apiquac-dev

Gestión de permisos: La carpeta fue configurada para que pertenezca al usuario baguer. Esto permite que las actualizaciones de código se puedan subir por FTP sin problemas de permisos bloqueados por el usuario root.

Comando utilizado para asignar la propiedad:

chown -R baguer:baguer /home/apiquac-dev

Servicio de segundo plano (Systemd)

Para garantizar que la API de .NET se ejecute de forma continua, se inicie con el servidor y se recupere ante fallos, se creó un servicio demonio en Linux.

Parámetro Valor
Nombre del servicioapiquac-dev.service
Archivo de configuración/etc/systemd/system/apiquac-dev.service
Directorio de trabajo/home/apiquac-dev
Comando de ejecución/usr/bin/dotnet /home/apiquac-dev/[NombreDeTuDll].dll
Variable de entornoASPNETCORE_ENVIRONMENT=Production
URL interna de escuchahttp://127.0.0.1:5005

Importante: Reemplaza [NombreDeTuDll].dll con el nombre real del archivo DLL generado por dotnet publish (por ejemplo: ApiQuac.dll).

Servidor web y proxy inverso (Nginx)

Nginx está configurado como reverse proxy para recibir el tráfico de internet a través de los puertos 80 (HTTP) y 443 (HTTPS) y redirigirlo internamente al puerto 5005 de la API.

Parámetro Valor
Archivo de configuración/etc/nginx/conf.d/apiquac-dev.conf
Redirección HTTP → HTTPS301 permanente (puerto 80 → 443)
Certificado SSL/etc/nginx/ssl/baguer_app_wildcard/baguer_app_fullchain.crt
Llave privada SSL/etc/nginx/ssl/baguer_app_wildcard/baguer_app.key

Certificado Wildcard: Se reutiliza el certificado corporativo *.baguer.app ya existente. No es necesario emitir ni renovar un certificado específico para este entorno.

Guía operativa — Comandos frecuentes

Flujo estándar para actualizar la API con nuevos cambios de código:

1

Subir archivos por FTP

Sube los nuevos archivos compilados a /home/apiquac-dev con el usuario baguer. Puedes sobreescribir los archivos existentes directamente.

2

Reiniciar el servicio

Conéctate por SSH y ejecuta el siguiente comando para que la API tome los nuevos cambios:

sudo systemctl restart apiquac-dev.service
3

Ver los logs en tiempo real (opcional)

Si la API falla o quieres monitorear la consola en vivo después del reinicio:

sudo journalctl -u apiquac-dev.service -f
