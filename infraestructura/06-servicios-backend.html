RegistroServiciosExternos

Tabla de log inmutable — cada llamada HTTP a un servicio externo genera exactamente una fila. Permite auditoría completa, replay y análisis de tiempos.

Sin ClaveIdempotencia. La máquina de estados controla duplicados a nivel de estudio — no se requiere ClaveIdempotencia en el log de servicios. Si un paso se repite (p.ej. reenvío de OTP), se inserta una nueva fila con la nueva invocación.

DDL de la tabla

CREATE TABLE RegistroServiciosExternos (
    IdRegistro          BIGINT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    IdPaso              INT           NOT NULL,
    NombreServicio      VARCHAR(100)  NOT NULL,
    PayloadRequest      NVARCHAR(MAX) NULL,     -- JSON enviado
    PayloadResponse     NVARCHAR(MAX) NULL,     -- JSON recibido
    CodigoHTTPRespuesta INT           NULL,
    ResultadoInterpretado VARCHAR(20) NOT NULL
        CHECK (ResultadoInterpretado IN
               ('EXITOSO','FALLIDO','TIMEOUT','ERROR')),
    DuracionMs          INT           NULL,
    FechaInvocacion     DATETIME2     NOT NULL DEFAULT GETUTCDATE(),
    FechaRespuesta      DATETIME2     NULL,

    CONSTRAINT FK_RegServ_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio),
    CONSTRAINT FK_RegServ_Paso FOREIGN KEY (IdPaso)
        REFERENCES PasosEstudio(IdPaso)
);

EvaluacionesRiesgo

Almacena el resultado de cada evaluación de riesgo ejecutada durante el paso VALIDAR_LISTAS, CONSULTAR_BURO, EVALUAR_PRESELECTA, VALIDAR_FOSYGA y CALCULAR_CUPO. El campo TipoEvaluacion fue ampliado en el gap G-DB-03 para incluir ANTECEDENTES y UBICA.

DDL de la tabla

CREATE TABLE EvaluacionesRiesgo (
    IdEvaluacion        INT IDENTITY(1,1) PRIMARY KEY,
    IdEstudio           INT           NOT NULL,
    TipoEvaluacion      VARCHAR(30)   NOT NULL
        CHECK (TipoEvaluacion IN (
            'BURO_CREDITO','LISTAS_RESTRICTIVAS','PRESELECTA',
            'MOTOR_CUPO','FOSYGA','ANTECEDENTES','UBICA')),
    ResultadoEvaluacion VARCHAR(20)   NOT NULL
        CHECK (ResultadoEvaluacion IN ('APROBADO','RECHAZADO','PENDIENTE','ERROR')),
    ScoreObtenido       DECIMAL(10,4) NULL,
    DetalleResultado    NVARCHAR(MAX) NULL,
    FechaEvaluacion     DATETIME2     NOT NULL DEFAULT GETUTCDATE(),
    IdOperador          INT           NULL,

    CONSTRAINT FK_EvalRiesgo_Estudio FOREIGN KEY (IdEstudio)
        REFERENCES EstudiosCredito(IdEstudio)
);

Patrón BFF por Capas

El backend sigue un patrón Backend for Frontend (BFF) — cada canal (WEB, TIENDA, ADMIN) tiene su propio adaptador de entrada que normaliza la petición antes de llegar al núcleo de la fábrica.

┌──────────────────────────────────────────────────────────┐
│                   CANALES DE ENTRADA                     │
│   [ASESOR TIENDA]    [PORTAL WEB]    [ADMIN / FÁBRICA]   │
│        ↓                  ↓                  ↓           │
│   JWT_ORIGEN_TIENDA   JWT_ORIGEN_WEB    JWT_ADMIN         │
└──────────────────┬───────────────────────────────────────┘
                   │  BFF Layer (normalización y auth)
                   ▼
┌──────────────────────────────────────────────────────────┐
│              NÚCLEO DE FÁBRICAS (Core)                   │
│                                                          │
│  EstudiosCredito ──→ MáquinaEstados ──→ PasosEstudio     │
│         │                                    │           │
│         ▼                                    ▼           │
│  EvaluacionesRiesgo           RegistroServiciosExternos  │
└──────────────────┬───────────────────────────────────────┘
                   │  Adaptadores de salida
                   ▼
┌──────────────────────────────────────────────────────────┐
│               SERVICIOS EXTERNOS                         │
│  ERP_QUAC │ CORE_CREDITO │ OTP_PROVIDER │ BURO_CREDITO  │

Reglas de integración

  • Toda invocación a servicio externo genera una fila en RegistroServiciosExternos — sin excepción.
  • Reintentos generan filas nuevas — no se sobreescribe la fila anterior.
  • Timeouts se registran con ResultadoInterpretado = 'TIMEOUT' y FechaRespuesta = NULL.
  • Los payloads (PayloadRequest, PayloadResponse) se almacenan como JSON en NVARCHAR(MAX) — no se parsean en la base de datos.
  • DuracionMs = diferencia en milisegundos entre FechaInvocacion y FechaRespuesta; puede ser NULL si la respuesta no llegó.

Datos sensibles en payloads. Los campos PayloadRequest y PayloadResponse pueden contener PII. El acceso a esta tabla debe restringirse al rol de auditoría (ROL_AUDITORIA_FABRICAS). No exponer estos campos en APIs de consulta estándar.
