Diseño Unificado v2.5 (GAP-07)

FotografiasEstudio unifica selfie y documentos. A partir de v2.5 (GAP-07), la tabla FotografiasEstudio gestiona el ciclo de vida completo de las 3 fotos obligatorias — SELFIE, DOCUMENTO_FRONTAL y DOCUMENTO_TRASERO — en una sola tabla con datos biométricos inline. CatalogoTiposFotografia permanece como catálogo de referencia pero ya no actúa como bloqueo del diseño.

Los 3 tipos de foto (orden del flujo de prueba de vida)

OrdenTipoFotografia (CHECK)Servicio AWSObligatoriaDescripción
1SELFIEREKOGNITION_DETECT_FACESSíPrueba de vida (persona real y viva). Comparada con la foto frontal del documento.
2DOCUMENTO_FRONTALREKOGNITION_DETECT_LABELSSíFrente de la cédula — OCR de nombre, doc, fecha exp. Comparación facial contra selfie.
3DOCUMENTO_TRASEROREKOGNITION_DETECT_LABELSSíReverso de la cédula — OCR de grupo sanguíneo, huella, código de barras.

Regla de negocio: el cliente DEBE tener exactamente 3 filas con EsVigente = 1 y EstadoRevision IN ('APROBADA_AUTO','APROBADA_ASESOR') para que el gate de aprobación de crédito sea superado. El índice único filtrado UQ_FotografiasEstudio_Vigente garantiza que solo haya una foto vigente por tipo por estudio.

Flujo Completo de Fotografías


 [Cliente inicia VERIFICACION_IDENTIDAD]
      │
      ▼
 Sistema genera 3 entradas en FotografiasEstudio (EsVigente=1, EstadoRevision=PENDIENTE)
      │
      ├─ SELFIE capturado → EstadoRevision = APROBADA_AUTO (si Rekognition ok)
      ├─ DOCUMENTO_FRONTAL capturado → OCR + CompareFaces
      └─ DOCUMENTO_TRASERO capturado → OCR código de barras
      │
      ▼
 ¿Todas aprobadas automáticamente?
      ├─ SÍ → EstudiosCredito.FotografiasAprobadas = 3
      │         EstadoRevisionFotos = 'APROBADAS'
      │         → Continuar flujo (EN_PROGRESO)
      │
      └─ NO → EstadoRevision = RECHAZADA en la(s) foto(s) fallida(s)
               EstadoRevisionFotos = 'RECHAZADAS' o 'PENDIENTE'
               Estado del estudio → PENDIENTE_FOTOS
               │
               ├─ Sistema genera SolicitudesRecarga (TokenRecarga único)
               │   CanalEnvio: WHATSAPP (defecto configurable)
               │
               ▼
          [Cliente usa link de re-carga]
               │
               ├─ Sube foto → EsVigente anterior = 0 (REEMPLAZADA)
               │             Nueva fila FotografiasEstudio (EsVigente=1)
               │             Estado → FOTOS_EN_REVISION
               │
               ▼
          [Asesor revisa en módulo]
               │
               ├─ APROBADA → RevisionesFotografia INSERT, foto.EstadoRevision = APROBADA_ASESOR
               └─ RECHAZADA → RevisionesFotografia INSERT con CodigoMotivoRechazo
                              Estado → PENDIENTE_FOTOS (nuevo link)

Parámetros de configuración (ConfiguracionReglasNegocio, Categoria = 'FOTOS'):
VIGENCIA_LINK_RECARGA_HORAS = 48 · MAX_REINTENTOS_RECARGA_FOTO = 3 · MAX_VERSIONES_FOTO = 4 · FOTOS_OBLIGATORIAS_REQUERIDAS = 3 · CANAL_DEFECTO_RECARGA = WHATSAPP · ALERTA_FOTO_RECHAZADA_VECES = 2
