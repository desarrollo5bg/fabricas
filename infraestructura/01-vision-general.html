Descripción del sistema LOS

Las Fábricas de Crédito QUAC implementan un Loan Origination System (LOS) para la originación de crédito al consumo en Colombia. El sistema soporta el ciclo de vida completo de una solicitud de cupo de crédito: desde la identificación del cliente hasta la activación del cupo en el core bancario.

El proceso está orquestado por una máquina de estados finita parametrizable (15 estados, 40+ transiciones) con soporte para múltiples canales de origen, validaciones de riesgo, verificación biométrica facial, módulo de fotografías y detección de fraude en tiempo real.

Canales de origen

El sistema soporta tres canales, definidos en la tabla CatalogoCanalesOrigen:

Canal WEB

Autoservicio digital

El cliente inicia el proceso desde el portal web o app móvil sin asistencia. No requiere asesor. JWT generado con origen LoginWeb.

AUTOSERVICIO

Canal TIENDA

Punto de venta asistido

El asesor asiste al cliente en tienda/bodega. Requiere validación biométrica del asesor (ValidacionesAsesor). JWT con origen LoginTienda.

ASISTIDO

Canal EXTERNO

Fuerza de ventas

Originación por vendedores externos o aliados comerciales. Usa kcrm_VendedoresExternos (tabla existente en PRUEBASBD).

EXTERNO

Canal RENOVACIÓN: El sistema soporta estudios de reactivación mediante la bandera EsReactivacion = 1 en EstudiosCredito y la configuración DIAS_CANCELACION_REACTIV en ConfiguracionReglasNegocio. No es un canal separado en el catálogo.

Arquitectura en capas

El modelo de datos soporta la siguiente arquitectura de servicios:

1

API Gateway

Autenticación JWT, enrutamiento por canal (LoginWeb / LoginTienda), rate limiting, correlación de requests (IdCorrelacion)

↕ JWT con claim origen
2

BFF (Backend for Frontend)

Adaptadores por canal. Canal WEB usa flujo autoservicio. Canal TIENDA valida asesor previamente. Construye respuesta optimizada por contexto.

↕ Servicios internos
3

Microservicios de dominio

Servicios de: Originación, Biometría (AWS Rekognition), Riesgo (Buró, Preselecta, FOSYGA), OTP (WhatsApp/SMS/Email), Contactabilidad (UBICA), Antifraude

↕ Dapper + Stored Procedures
4

Base de datos — SQL Server 2019+

31 tablas propias + tablas existentes QUAC (terceros, bodegas, KCRM_CadenaCreditos). Máquina de estados + auditoría inmutable. GAP-19: operadores gestionados vía fab.OperadoresFabrica y fab.DisponibilidadOperadores.

Grupos funcionales

Las 31 tablas del proyecto se organizan en 6 grupos funcionales:

GrupoTablasPropósito
Configuración 7 Parametrizan el flujo: estados, transiciones, fases, pasos, canales, reglas de negocio, operadores
Transaccional 10 Registran operaciones del proceso: estudios, retos OTP, biometría, contactabilidad, consentimientos, evidencias, escalamientos, validación asesor, fotografías, solicitudes recarga, disponibilidad operadores
Auditoría 5 Trazabilidad inmutable (INSERT-ONLY): historial de estados, cambios de datos, servicios externos, revisiones de foto, historial de fotos
Antifraude 4 Detección y trazabilidad de fraude: catálogos de reglas y motivos, alertas (INSERT-ONLY), log OTP (INSERT-ONLY), datos sensibles (INSERT-ONLY)
Seguridad 2 ValidacionesAsesor (biometría del asesor) y AuditoriaLogins (todos los intentos de login)
Integración 1 TercerosFabricas: fuente de verdad del proceso, sincroniza con QUAC.dbo.terceros
